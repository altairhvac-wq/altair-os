## Working notes

- Dashboard and Reports are done reference points — reuse their components/tokens.
- Surface style decision: all panels from #2 onward use MC v2 (mc-surface.ts), not Reports' report-surface.ts. Reports keeps its own distinct treatment.
- Dispatch exception: dark ops-command treatment instead of light MC v2, deliberately chosen for real-time boards. Schedule (#14) follows the same treatment.
- Time-block width rule: on any time-axis board, job blocks are fixed-width start-time markers, never stretched to imply duration, since scheduled_end/job duration doesn't reliably exist.
- Leads is no longer a standalone panel — it lives as the Lead Pipeline tab on the Customers hub. Do not reintroduce a sidebar Leads entry or a fake Referrals tab; customer-to-customer referral tracking is separate future work (distinct from Network B2B `network_referrals` and technician `member_share_code`).
- `/team` hosts a unified hub (Technicians, Time Clock tabs), same pattern as the Customers hub. Both panels embedded unchanged. Old `/technicians` and `/time-clock` routes redirect to `/team?tab=...`, deep links retargeted. Work nav group: Team replaces standalone Technicians item. "Manage permissions" links to `/settings/team` rather than duplicating role management. No Payroll or Performance tab — no honest data for either yet. Labor & payroll (`/time`) stays a separate Money nav item.
- Job Detail: new Time Tracking tab (`JobTimeTrackingSection`, real `listJobLaborEntriesForJob` data, closed-segment total). Work hub: `/work` hosts Jobs unchanged (Today/All, six status pills), header links to real `/dispatch` (not embedded — Dispatch's dark page stack has no embedded mode, forcing it into a hub tab would need real structural work). `/jobs` and `/jobs/[jobId]` redirect to `/work`, query params preserved. Sidebar: Jobs replaced by Work; Dispatch kept in Work group for now as fast access alongside the header link, flagged as droppable later. Deep links and `revalidatePath` retargeted across dashboard/customers/reports/notifications/activity/onboarding/estimates/invoices. No new job-status tab taxonomy — Active Jobs/Scheduled/Unscheduled/Completed/Archived from the original proposal didn't map cleanly onto real statuses (name collisions, orphaned statuses), so Jobs' existing real structure was kept instead.
